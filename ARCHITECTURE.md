# Engineering Architecture - Multimedia Club Platform

## 1. Architectural Philosophy
The Multimedia Club Platform is designed as a **Modular Monolith** using **CodeIgniter 4** (PHP 8.4) and **MySQL 8.4**. It prioritizes high maintainability, clear separation of concerns, transactional reliability, and seamless readiness for future REST API and mobile app extensions.

```
       +--------------------------------------------------------+
       |                  HTTP Request / Router                 |
       +--------------------------------------------------------+
                                   |
                                   v
       +--------------------------------------------------------+
       |           CodeIgniter Filters (Auth & RBAC)             |
       +--------------------------------------------------------+
                                   |
                                   v
       +--------------------------------------------------------+
       |             Thin Controller (app/Modules/*)            |
       |  - Request Validation & Parameter Extraction           |
       |  - Delegates Business Logic to Services                |
       |  - Formats HTML View / Standardized JSON Response      |
       +--------------------------------------------------------+
                                   |
                                   v
       +--------------------------------------------------------+
       |                 Service Layer (Services)               |
       |  - Business Rules & Workflow Logic                      |
       |  - DB Transactions ($db->transStart / transComplete)   |
       |  - QR Token Generation & Crypto Operations             |
       |  - Audit Log & Notification Dispatcher                 |
       +--------------------------------------------------------+
                                   |
                                   v
       +--------------------------------------------------------+
       |                     Model Layer                        |
       |  - Database CRUD Operations                            |
       |  - Entity Query Builder & Joins                        |
       |  - Soft Deletes Handling                               |
       +--------------------------------------------------------+
                                   |
                                   v
       +--------------------------------------------------------+
       |                    MySQL Database                      |
       +--------------------------------------------------------+
```

## 2. Core Engineering Principles

### 2.1 Thin Controllers & Rich Service Layer
- **Controllers** (`app/Modules/{Domain}/Controllers/`): Keep zero business logic. Controllers receive incoming HTTP requests, run CodeIgniter validation rules, invoke the corresponding Service method, and return rendered views or standardized JSON responses.
- **Services** (`app/Modules/{Domain}/Services/`): All domain logic lives inside Services. Complex multi-table operations (e.g. attendance scan verification, meeting activation, task submission evaluation) are executed within database transactions (`transStart()` / `transComplete()`).

### 2.2 Public Identifier Strategy (UUID vs Auto-Increment Primary Keys)
- **Primary Keys (`id`)**: Internal auto-increment integers used exclusively for fast database index joins and foreign key constraints.
- **Public Identifiers (`uuid`, `member_uuid`, `qr_token`)**: Standard UUID v4 strings used in public routes, URLs, forms, QR codes, and API endpoints. Internal primary keys are never exposed in public parameters.

### 2.3 Permanent Member QR vs Dynamic Meeting QR
- **Member Permanent QR**: Contains strictly the `member_uuid` string. Does not contain sensitive personal info. Can be regenerated by the member or admin, which increments `qr_version` and invalidates the previous UUID instantly.
- **Meeting QR**: Contains a dynamic, cryptographically random `qr_token` generated when a meeting is transitioned to `active` status.

### 2.4 Consistent API / AJAX JSON Contract
All AJAX endpoints return a standardized JSON format:
```json
{
  "status": "success" | "error" | "warning",
  "message": "Human readable message",
  "data": { ... }
}
```

### 2.5 Security & Role-Based Access Control (RBAC)
- **AuthFilter**: Verifies session state (`is_logged_in`).
- **RoleFilter**: Enforces role permissions across 4 roles:
  1. `superadmin`: Full system access, configurations, audit logs.
  2. `pembina`: Meetings, attendance, tasks, member management.
  3. `bph`: Meetings, attendance, tasks, submissions evaluation.
  4. `member`: Attendance scanner, personal attendance history, task portal, member profile.
- **Password Security**: Passwords hashed using `password_hash(..., PASSWORD_BCRYPT)`.
- **CSRF Protection**: Native CodeIgniter CSRF tokens enforced on all POST forms.
